# WPGuard

Локальный сканер безопасности WordPress. Проверяет файлы сайта и, если есть доступ, базу данных на том компьютере, где запущен. Содержимое сайта никуда не отправляется.

Программа сверяет ядро и плагины из каталога WordPress с официальными контрольными суммами, ищет известные уязвимости в [WPVulnerability](https://www.wpvulnerability.net/) и отмечает подозрительный код по открытым правилам. Это проверка уже лежащих файлов, а не защита в момент запроса.

## Установка

Нужен Python 3.10 или новее.

```bash
cd wp-guard
python -m pip install .
wp-guard version
```

Если нет прав устанавливать пакеты для всей системы:

```bash
python3 -m pip install --user .
```

Команда `wp-guard` при этом ставится в `~/.local/bin`. Пока каталог не в `PATH`, её можно вызвать так:

```bash
~/.local/bin/wp-guard version
```

Чтобы оболочка находила команду без полного пути, добавьте каталог на текущую сессию:

```bash
export PATH="$HOME/.local/bin:$PATH"
wp-guard version
```

Чтобы это сохранилось после нового входа по SSH, допишите ту же строку в файл настроек оболочки и примените его:

```bash
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.bashrc
source ~/.bashrc
```

На macOS с оболочкой zsh файл называется `~/.zshrc`, а команда применения — `source ~/.zshrc`.

## Проверка сайта

Полная проверка каталога, в котором лежит WordPress:

```bash
wp-guard scan /путь/к/сайту
```

Если сайтов в каталоге несколько, проверяются все найденные. Версию PHP сайта лучше указать явно — от неё зависит, попадут ли в отчёт уязвимости самой версии PHP:

```bash
wp-guard scan /путь/к/сайту --php-version 8.3.16
```

Отдельные проверки:

```bash
wp-guard malware-scan /путь/к/сайту
wp-guard integrity-scan /путь/к/сайту
wp-guard vuln-scan /путь/к/сайту --php-version 8.3.16
wp-guard db-scan /путь/к/сайту
```

Отчёт печатается в консоль и записывается в `~/wp-guard-report.txt`. Свой файл и формат задаются так:

```bash
wp-guard scan /путь/к/сайту --format json --output ~/wp-guard-report.json
```

Форматы: `text`, `json`, `csv`.

Код выхода: `0` — нет критичных и высоких замечаний, `2` — они есть, `1` — проверка не запустилась.

### База данных

Параметры подключения читаются из `wp-config.php`. Если пароль задан не прямо в файле, передайте его переменной окружения:

```bash
# Linux, macOS
export WP_GUARD_DB_PASSWORD=секрет

# Windows
set WP_GUARD_DB_PASSWORD=секрет

wp-guard scan /путь/к/сайту
```

Проверка базы только читает данные. Пароль в отчёт не попадает.

### Полезные параметры

- `--workers 2` — сколько файлов смотреть параллельно. На слабом хостинге достаточно `1` или `2`.
- `--offline` — не обращаться к wordpress.org и к базе уязвимостей.
- `--refresh` — заново скачать контрольные суммы и список уязвимостей.
- `--min-severity high` — оставить только высокие и критичные замечания.
- `--quiet` — не печатать ход проверки.

Список всех параметров: `wp-guard scan --help`.

### Проверка в фоне

Чтобы проверка продолжилась после закрытия SSH:

```bash
wp-guard scan /путь/к/сайту --background
wp-guard status
wp-guard stop
```

Пока проверка идёт, в файле отчёта написано, что результат ещё не готов. Журнал хода работы лежит в `~/.cache/wp-guard/scan.log`.

## Что попадает в отчёт

**Подозрительные файлы.** PHP, HTML, JS и служебные файлы вроде `.htaccess`. Отмечаются типичные приёмы вредоносного кода, PHP в каталоге загрузок, двойные расширения, копии `wp-config`, дампы базы и лишние drop-in и must-use плагины.

**Целостность.** Файлы ядра и официальных плагинов сравниваются с контрольными суммами wordpress.org. Изменённый или лишний PHP в ядре — критичное замечание. Плагина нет в каталоге — это справка: платные и самописные туда не входят. У тем официальных контрольных сумм нет, они проверяются правилами и базой уязвимостей.

**Уязвимости.** Версии ядра, плагинов (в том числе выключенных), тем, PHP и MySQL/MariaDB сравниваются с известными уязвимостями. Отдельно отмечаются устаревшие и закрытые в каталоге компоненты.

**База.** Учётные записи администраторов, подозрительные настройки, PHP и `eval` в опциях, записях и cron, открытая регистрация и роль по умолчанию `administrator`.

**Настройки сайта.** Редактор файлов в админке, показ ошибок, короткий пароль базы, `xmlrpc.php` и слишком открытые права на файлы.

Свежий вредоносный код в самописном плагине может не совпасть ни с одним правилом. После критичных находок стоит отдельно посмотреть недавние PHP-файлы и список администраторов.

## Восстановление

Сначала программа только показывает, что собирается сделать. Файлы меняются после `--apply`.

```bash
wp-guard remediate /путь/к/сайту
wp-guard remediate /путь/к/сайту --apply
wp-guard remediate /путь/к/сайту --apply --quarantine
```

`--apply` заменяет изменённые файлы ядра и официальных плагинов копиями с wordpress.org. Файл записывается только если скачанная копия совпала с контрольной суммой. Прежняя версия сохраняется в `~/.cache/wp-guard/backups`.

`--quarantine` переносит явно опасные файлы в `~/.cache/wp-guard/quarantine`. `wp-config.php` и `.htaccess` программа не трогает.

Перед `--apply` сделайте свою резервную копию сайта.
